# ML_ROADMAP.md

High-level plan for evolving the Rehoboam ML layer from the current z-score divergence check into a predictive, proactive system.

## 0. Today – Baseline divergence model

- Inputs: `history.json` entries generated by `state_engine_service` (already include per-LED health/activity plus contextual flags such as `daypart`, `occupancy`, and `rain_expected` when configured).  
- Output: `divergence.json` with `score`, `level`, `metrics`, and an embedded `recommendations` array populated by simple rule hooks (rain-before-blinds, repeated errors).  
- Distribution: `/divergence` and `/recommendations` endpoints, dashboards, e-ink scenes, CLI, and HA REST sensors.

## 1. Data enrichment

| Goal | Implementation detail | Owner |
| --- | --- | --- |
| Capture richer context | Configure `collector_service` `context_entities` (weather, occupancy, UPS sensors) and ensure they flow into `history.json`. | Collector + State Engine |
| Event tagging | Extend `collector_service` event normalization to include `event_tags` (e.g., `blind_auto_close`, `breaker_flip`), store the latest tags in each history entry. | Collector |
| Rate-of-change signals | Have `state_engine_service` compute deltas (Pi-hole QPS slope, error_count trend) and append to `history.json`. | State Engine |
| Persistence | Consider a rolling `features.json` artifact that keeps normalized vectors for the last N snapshots to simplify downstream training. | ML service |

## 2. Feature extraction & modeling

1. **Transparent rules:** Maintain YAML-driven rules (close blinds before rain, reboot Pi-hole after repeated errors). These power the current recommendations array.  
2. **Unsupervised anomalies:** Introduce `scikit-learn` matrices (Isolation Forest or One-Class SVM) trained on the enriched feature set. Models run every few minutes; store outputs alongside the z-score metrics for comparison.  
3. **Sequence learning (optional):** Evaluate TF Lite or `statsmodels` seasonal decomposition to predict “expected” behavior for each LED/time-of-day. Deviations become proactive hints (“Mac mini usually online by 8 AM, but it’s still offline”).  
4. **Model ops:** Version any heavier models under `data/models/` with metadata (`model_version`, feature list, training window) so services can roll back if needed.

## 3. Recommendation lifecycle

| Stage | Artifact | Detail |
| --- | --- | --- |
| Generation | `divergence.json.recommendations[]` | Each entry includes `id`, `timestamp`, `trigger`, `target`, `suggestion`, `confidence`, `priority`, optional `actions` (e.g., `{"service": "homeassistant", "call": "script.close_blinds"}`). |
| API | `/recommendations` | Returns `{generated_at, timestamp, recommendations}` for easy HA/CLI consumption. |
| Feedback | `events.json` + optional `recommendations_state.json` | Track when HA applies/ignores a suggestion (e.g., automation toggles `status` to `applied`). Feed that data back into the ML service to adjust confidence scores. |
| Delivery | Dashboards, CLI, MQTT | Web dashboard and e-ink scenes show active recommendations; future MQTT topics (`rehoboam/recommendations/<id>`) enable push notifications. |

## 4. Integration with Home Assistant

- **REST sensors**: Create HA sensors that poll `/divergence` and `/recommendations`, then use automations to act (flash lights when level == divergent, auto-run scripts for certain suggestions).  
- **Helpers as feedback**: Add `input_boolean.rehoboam_ack_recommendations` or `input_text.rehoboam_last_action` so HA users can confirm an action; collector/ML services read those helpers to close the loop.  
- **Automations library**: Document recommended HA automations (under `docs/home_assistant.md`) that map suggestions to safe actions (e.g., call `script.close_blinds` only if occupancy is detected).

## 5. UX & Dev Tools

- **Dashboards**: Extend `devtools/dashboard/` to call `/recommendations` directly and show per-suggestion context (confidence, action buttons).  
- **CLI**: `devtools/cli.py` already prints suggestions; enhance it with flags (`--ack <id>`, `--json`) once the feedback loop is in place.  
- **E-ink scenes**: Add a “Recommendations” scene listing the top N suggestions with icons (blind, network, climate).  
- **Documentation**: Keep this roadmap updated alongside `jetson/ml_service/README.md` whenever new features land so the predictive journey stays transparent.

## 6. Testing & Validation

- Unit tests cover schema generation (`tests/test_ml_service.py`, `tests/test_divergence_model.py`).  
- Add golden samples for recommendations (e.g., `samples/divergence.recommendations.sample.json`) once the feature set stabilizes.  
- For ML experiments, capture notebooks or scripts under `devtools/ml/` with synthetic data so reviewers can reproduce results before deploying to the Jetson.
